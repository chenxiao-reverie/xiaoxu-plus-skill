## 一、8 项评分卡逐项判定

### 1. 目标可量化

**通过**：北极星指标 + 基线 + 目标值/方向，三者齐备。
> ✅ 「周报汇总耗时从每周 6 小时降到 1 小时以内」
> ❌ 「提升周报效率」——基线和目标值都缺，等于没有目标

**典型伪装**：「显著提升」「大幅降低」「业界领先」。凡是没数字也没方向的，一律不通过。

### 2. 范围有边界

**通过**：明确列出「本期不做」≥2 项，且不做项与目标不冲突。
> ✅ 「做：数据自动拉取、周报模板生成。不做：权限体系、移动端、历史数据回填。」
> ❌ 「先做核心功能，后面再补」——「核心」没定义，等于没有边界

**为什么要求不做 ≥2 项**：只描述做什么，范围会随对话无限膨胀；必须靠排除法锁死。

### 3. 用户与场景具体

**通过**：主角色 + 触发场景，不含「所有人」「随时随地」「有需要的人」。
> ✅ 「销售运营专员，每周五下午要出周报时打开」
> ❌ 「全公司需要看数据的人」

加分项：明确写出「不服务谁」。

### 4. 约束已量化

**通过**：时间 / 预算 / 人力 / 技术栈 / 合规 中 ≥3 项有具体数值或硬边界。
> ✅ 「11 月 30 日前上线；预算 5 万内；我一个人做，每周可投入 8 小时」
> ❌ 「越快越好，预算看情况，没什么技术要求」

说「没限制」往往等于还没想过。给区间选项，别继续追问。

### 5. 成功标准可验证

**通过**：交付时能用**一个可观测动作**判定成败。
> ✅ 「上线后第一个周五，运营没手动打开 Excel，周报自动生成且老板没让返工」
> ❌ 「用户满意」「跑通就行」

**检验方法**：把标准读给一个不相干的人听，他能判断「过了 / 没过」吗？不能就是不通过。

### 6. 关键假设已验证

**通过**：假设台账中所有 P0 假设状态为「已证实」或「用户明确承接风险」。
> P1 假设可留待验证，但必须在确凿书中标注。

**P0 的定义**：这一条错了，整个需求作废。例：「数据源有 API 可拉」——如果没有，整个自动化方案不成立。

### 7. 反例已排除

**通过**：≥1 条被明确否决的替代方案 + 否决理由。
> ✅ 「否决了 Excel 模板方案：无法解决数据对不上的问题，只是把人工搬到线上」
> ❌ 从头到尾只有一个方案，没比较过

没有比较过的方案，无法证明它是最优解。否决记录也是未来复盘的关键材料。

### 8. 用户明确签字

**通过**：用户对合并后的一句话需求陈述给出确认，确认标准按当前模式判定（见第四节）。

**核心要求不变**：§0 的一句话陈述必须被用户**读过**，不能只在 AI 内部生成。

## 二、打分方法

- 逐项判 `✓` / `✗`，**不做 0.5 分**（半通过等于不通过）
- 总分 = ✓ 的数量
- **单轮涨幅超过 3 分需回查**：用户是否一次性给了完整 brief？还是 AI 把推测当成了确证？

**进度条格式**（每轮末尾展示）：
```
确凿度 5/8  ▰▰▰▰▰▱▱▱
待补：④ 约束量化 ｜ ⑦ 反例排除 ｜ ⑧ 用户签字
```

## 三、三档处理

| 得分 | 动作 |
|------|------|
| **8/8** | 输出《需求确凿书》，结束 |
| **6–7** | 告知缺口，二选一：补齐 / 按现状收敛（必须附未确证项声明） |
| **≤5** | 回定靶，继续 Loop。不解释、不输出框架 |

### 6–7 分收敛的强制声明

按现状收敛时，确凿书开头必须加：

```
⚠️ 未确证项（用户选择按现状收敛）
- ④ 约束量化：预算未定，暂按「万元级」假设推进
- ⑦ 反例排除：未比较过自建方案

影响：若上述假设不成立，<具体后果>。建议在 <阶段> 前完成验证。
```

**不写声明的收敛，等于假收敛。**

## 四、双模式判定细则

| | 严格模式 | 宽松模式（默认） |
|---|---------|-----------------|
| 判定口径 | 必须出现明确确认表述 | 未提出修改意见即视为确认 |
| 视为确认 | 「确认无误」「就是这个」「对，按这个做」「没问题，开工」 | 上述任一，或「可以」「行」「收到」「下一步」「直接开工」，或直接布置执行类新任务 |
| 不视为确认 | 「可以」「还行」「嗯」「差不多」「你看着办」 | 继续提修改意见、追问细节、未回应；出现「差不多」「你看着办」仍判 ✗ |

**确定与切换**：首轮配置组 Q1 明确问一次，并把差异摆给用户看；跳过则用默认的宽松模式。中途说「严格模式」/「宽松模式」即切换，会话内生效。**同一会话内不重复问已确认的模式。**

### 两条边界

1. **宽松不等于免检。** 第 8 项仍必须打勾，只是证据形态从「明确表述」放宽到「无异议 + 有回应」。
2. **宽松不豁免假收敛信号。** 命中任一信号，两种模式都不许收敛。

### 用户沉默怎么办

- 确凿书已输出，用户**未回应** → 第 8 项判 ✗，不视为确认
- 确凿书已输出，用户接着问执行细节（「那数据从哪拉」「什么时候能开工」）→ **视为确认**（已越过讨论需求本身）

> 分界线：讨论「需求对不对」= 还没确认；讨论「怎么实现」= 已经确认。

## 五、假收敛的 5 个信号

命中任一，**不许收敛**，先处理根因。

| # | 信号 | 根因 | 处理 |
|---|------|------|------|
| 1 | 用户连续 3 次答「都行 / 随便 / 你定」 | 不是共识，是疲劳 | 停止提问，给 2 个完整方案让用户挑一个（二选一压力小于开放题） |
| 2 | 8 项里有 3 项以上由 AI 推测填入 | 把推测当确证 | 每项推测标 `⚠️待验证`，评分卡判 ✗ |
| 3 | 评分卡过了，但一句话陈述用户没读过 | 用户没真正对齐 | 单独发出陈述，要求复述或确认 |
| 4 | 约束项全是「没限制」 | 还没想过 | 不允许通过，用区间选项重问 |
| 5 | 单轮从 4 分跳到 8 分 | 用户在敷衍，或 AI 在凑分 | 回查每项证据来源，无证据的降回 ✗ |

## 六、无进展熔断

**触发**：连续 2 轮总分不变。

**三步诊断**，按顺序查：

### ① 靶选错了吗？
问的这件事虽然未知，但**不阻塞收敛**（纠结按钮文案，而预算还没定）。
→ 换靶，回到阻塞度排序。

### ② 题型错了吗？
一直用选择题问一个用户其实没有偏好的事。
→ 换题型（选择题 → 场景题 → 反例题 → 极端题）。

### ③ 用户在回避吗？
反复说不清、绕开某个维度、回答变短。常见原因：组织政治（不方便说谁反对）、预算隐情（钱还没批）、自己也没想好（怕说错）。

→ 不追问内容，直接问顾虑：
> 「这块我连着问了两轮都没问出来，是不是有什么不方便说的？比如预算还没定、或者上面还有人要点头？我们先把卡点说清楚，方案可以分两种走。」

**熔断不是失败。** 卡住时诚实说出来，比继续问第 12 轮有价值。

## 七、收敛后的动作

1. 输出《需求确凿书》（模板见 `output-spec.md`）
2. 展示最终评分（8 项逐项 ✓，附一行证据摘要）
3. 推荐 1–3 个真实存在的技能（按三层降级策略）
4. 问一句：「这份确凿书要直接转成开发任务，还是先给你调整？」

**不要**在交付后又开始问新问题——收敛就是收敛。有新发现记进「开放问题」章节，留给下一轮迭代。
