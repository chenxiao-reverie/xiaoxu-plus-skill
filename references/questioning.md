## 一、需求状态机 8 维

每维要能回答三件事：合格答案长什么样 / 常见的不合格答案 / 用什么探针问出来。

### 1. 问题定义

**合格**：`角色` 在 `场景` 下，因为 `阻碍`，导致 `后果`；目前靠 `替代方案` 顶着，但它不够，因为 `原因`。
**不合格**：「效率低」「不好用」「需要数字化」——这些是感受，不是问题。
**探针**：
- 上一次发生这件事是什么时候？当时你具体做了什么？
- 现在没这个东西，你们是怎么扛过去的？
- 如果一直不解决，半年后会怎样？

> 替代方案是必问项。**没有替代方案的问题，往往不是真问题。**

### 2. 目标指标

**合格**：北极星指标（1 个）+ 当前基线（数字）+ 目标值或方向 + 期限。
**不合格**：「提升效率」「做得更好」「先做出来看看」。
**探针**：
- 做成之后，哪个数字会变？现在这个数字是多少？
- 如果只能改一个指标，改哪个？
- 多久之内要看到变化？

### 3. 用户与场景

**合格**：1 个主角色 + 触发场景（何时、何地、手上有什么、想干什么）+ 明确不服务谁。
**不合格**：「所有人」「公司同事」「有需要的人」。
**探针**：
- 第一个打开它的人是谁？他当时正在做什么别的事？
- 谁最不会用它？为什么？
- 如果只服务一个人，是谁？

> 「不服务谁」比「服务谁」更能定边界，优先问。

### 4. 范围边界

**合格**：MVP 做 3–5 项 + 明确不做 ≥2 项，且不做项与目标不冲突。
**不合格**：只列一长串要做的功能，从不提不做什么。
**探针**：
- 这一版最想砍掉哪块？
- 哪个功能是「有了更好、没有也能上线」？
- 如果时间只够做一件事，做哪件？

### 5. 约束条件

**合格**：时间 / 预算 / 人力 / 技术栈 / 合规 中 ≥3 项有具体数值或硬边界。
**不合格**：「没什么限制」「越快越好」「预算看情况」。
**探针**：
- 死线是哪一天？那天要发生什么？
- 谁来做？他手上还有别的事吗？
- 有没有什么方案是「绝对不能碰」的？

> 说「没限制」通常意味着还没想过。此时给区间选项，比继续追问有效。

### 6. 验收标准

**合格**：交付时能用**一个可观测动作**判定成败。
**不合格**：「用户满意」「跑通就行」「看着不错」。
**探针**：
- 上线那天，你打开什么、看到什么，就算成了？
- 谁有权力说「这不合格」？
- 最可能被挑刺的是哪一点？

### 7. 假设与风险

**合格**：P0 假设全部有证据或用户明确承接。
**不合格**：假设散落在对话里，没人记录。
**探针**：
- 这件事成立的前提是什么？如果那个前提不成立呢？
- 你最担心哪一步出问题？

### 8. 决策记录

**合格**：每个关键分叉都有「选了什么 / 否了什么 / 为什么」。
**不合格**：只有结论，没有备选，未来无法复盘。
**探针**：不需要问用户，由 AI 自行记录。

## 二、五问法：按需下潜

| 层级 | 问题 | 目的 |
|------|------|------|
| 1 | 做什么？ | 明确表面动作 |
| 2 | 为什么？ | 挖动机 |
| 3 | 解决了什么？ | 看清价值 |
| 4 | 真正目的是？ | 触达本质 |
| 5 | 价值是什么？ | 定北极星 |

**规则**：
- 五问法是**最大深度**，不是**必须深度**
- 一旦答案已足以支撑决策（能定指标、能定范围），立即停止下潜
- 下潜产出的每一层都要写进状态机，不要只留在对话里

**反例**：
> 用户：「我要给销售做个业绩看板，因为老板每周要人工汇总三次，还老对不上数。」
> 这里已经在第 3 层。再问「那你为什么要看业绩？」是浪费耐心。
> 正确的下一步是问第 6 维：**「上线那天你打开看板看到什么，就算成了？」**

## 三、冰山模型：判断用户停在第几层

| 层 | 用户在说什么 | 语言信号 | 该做什么 |
|----|-------------|---------|---------|
| 👤 表层请求 | 「我想做个 X」 | 名词为主：做个 / 想要 / 需要一个 | 问**场景**，把名词还原成动作 |
| ⚠️ 困境 | 「每次都要…」「老是…」 | 负面频次词：总是 / 每次 / 来不及 / 对不上 | 问**后果**，量化损失 |
| 🔥 业务目标 | 「老板要…」「月底复盘…」 | 他人 + 场合：考核 / 汇报 / 投诉 / 审计 | 问**指标**，锁北极星 |
| 💡 价值 | 「不想再被质疑…」 | 情绪词：怕 / 担心 / 受够了 / 没底气 | 已经到底，转范围与约束 |

**起点判断**：看用户第一段话里的动词和情绪词。
- 只有名词 → 从第 2 层开始
- 有负面频次词 → 从第 3 层开始
- 有他人/场合 → 直接问指标
- 有情绪词 → 跳过下潜，问范围

## 四、四种题型

### A. 选择题（默认）

**适用**：有明确分叉、用户有偏好但说不清。

```
Q：这个看板主要给谁看？
为什么问：决定信息密度和权限模型，选错会导致做出来没人用。
选项：
  A. 一线销售自己看（推荐）—— 你提到「每周人工汇总」，痛点在一线重复劳动
  B. 销售主管看团队
  C. 老板看汇总
  D. 我不确定，你帮我判断
```

### B. 场景题（用户说不清抽象需求时）

**适用**：只会说「要更好用」「要智能一点」。

**做法**：不问意见，问**已发生的真实行为**。
> 「上周三你实际是怎么做这件事的？从打开电脑开始讲一遍。」

真实行为无法编造，能直接暴露卡点、工具、数据来源和绕过手段。

### C. 反例题（偏好类、审美类、取舍类）

**适用**：用户答不出「想要什么」，但答得出「不要什么」。

> 「A 方案：3 秒出结果但只能看当天；B 方案：要等 30 秒但能看任意时间段。你更受不了哪个？」

人对「排除」的判断力远强于「构建」。**先把错误答案排掉，剩下的就是需求。**

### D. 极端题（逼出优先级）

**适用**：功能列表越滚越长，什么都想要。

> 「如果这一版只能留一个功能，留哪个？」

答案往往和用户之前说的排序完全不同——这就是真实优先级。

## 五、模糊回答降维表

模糊回答**一律不放过**，但不要逼用户凭空想数字——给区间让他选。

| 模糊词 | 降维问法 |
|--------|---------|
| 快 / 马上 / 尽快 | 3 天内 / 1 周内 / 1 个月内 / 没有硬死线 |
| 简单 / 轻量 | 单页面单流程 / 单模块多流程 / 多模块 |
| 便宜 / 省点钱 | 千元级 / 万元级 / 十万元级 / 不能花钱（换人工方案） |
| 好用 | 少点击（≤3 步）/ 能批量 / 能手机操作 / 能离线 |
| 差不多 / 大概 | 给两个边界值：你宁可 A 还是宁可 B |
| 很多人 / 一些 | <10 / 10–100 / 100–1000 / >1000 |
| 高质量 | 谁验收 / 验收看哪三项 / 什么情况算不合格 |
| 灵活 / 可扩展 | 现在要支持几种情况 / 半年内可能新增几种 |
| 智能 / AI 一点 | 要它替你判断 / 替你生成 / 替你找出来 |

**降维后必须回填状态机**，确凿书里写用户选的那个区间，不要写模糊词。

## 六、选项设计规范

1. **2–4 个**。超过 4 个，用户会随机选或直接选「不知道」
2. **互斥**。A 和 B 不能同时成立
3. **覆盖主要分叉**。漏掉真实选项 = 逼用户选错的
4. **推荐位放第一个**，标「推荐」，理由必须引用调研证据（不是「我觉得」）
5. **必须留「不知道」出口**，且出口要具体：`我不确定，你帮我查` / `你替我定`
6. **不做假选择题**。只留一个合理答案的题，是在诱导，不是提问

## 七、12 道题怎么组织

单次出题上限 12 道，但**不是把 12 道并列抛出**。

### 结构

```
1–2 个阻塞靶（必答，决定本轮能否推进）
  +
最多 10 个伴随确认项（可跳，顺手补状态机）
  =
单次 ≤12 道
```

### 分组

按状态机维度分 2–4 组，每组 2–4 道：

```markdown
### 第 1 组 · 必答（决定下一步怎么做）
Q1 ...（阻塞靶）
Q2 ...

### 第 2 组 · 顺手确认（可跳，跳过我就按推荐项处理）
Q3 ... Q4 ... Q5 ...

### 第 3 组 · 约束（可跳）
Q6 ... Q7 ...
```

组间明确写一句：**「可以只答第 1 组，其余跳过我按推荐项推进。」**

### 三条硬规则

1. **阻塞靶只能是 1–2 个**。超过 2 个 = 没有排序 = 用户不知道先答哪个
2. **伴随确认项必须带默认值**。用户跳过时按推荐项推进，并记「AI 代决」入决议日志
3. **12 道是上限，不是目标**。能 3 道问清就不出 4 道——凑数会稀释必答题的分量

### 分批的判断

出现以下情况，即使没到 12 道也拆到下一轮：
- 上一批还有 ≥3 道未答
- 新一批的答案依赖上一批的结果（问了也白问）
- 用户回复变短、出现疲劳信号

### 首轮配置组（只问一次）

首轮的**第 1 组**固定是配置组，共 2 道，放在对齐表之后、正式追问之前。收敛后不再问。

关键：**必须把差异摊开写**，不能只丢「严格模式 / 宽松模式」两个术语让用户猜。

> **第 1 组 · 运行配置（2 道，之后不再问）**
>
> **Q1 这套需求按哪种模式走？**
> 为什么问：决定收尾时要不要你回一句确认，影响多花多少时间。
> - **A. 宽松模式（推荐）** —— 收尾不提修改意见就算通过，省一轮
> - B. 严格模式 —— 收尾必须回一句「确认无误」，适合要立项或对齐多方
>
> 差异：严格的差别只有一点——你得明确说「确认无误」；宽松是你不反对就算过。
> **追问密度和调研深度两种模式完全一样**，不会因为选了宽松就少问或少查。
>
> **Q2 最终产物要哪种格式？**
> 为什么问：决定交付文件长什么样，选错后面要返工重出。
> - **A. Markdown（推荐）** —— 单文件，方便继续编辑、入库、贴进文档
> - B. HTML —— 单文件网页，排版好看，适合发给人看或打印
> - C. 两者都要 —— 先出 Markdown 再转 HTML，内容一致
>
> 不选就按 Markdown。

**三条规则**：

1. 配置题不计入「阻塞靶」——它们是开局设定，不是需求澄清
2. 用户跳过 → 按默认值继续，并在对齐表下加一行「按默认：宽松 + Markdown」
3. 已确认过的不再问第二次；中途改主意，直接照新设定走，不回头重问

## 八、提问纪律

1. **不问已知** —— 先查状态机，问过的不要再问
2. **不问 AI 能查的** —— 先跑 L1，再开口
3. **不合并维度** ——「要什么功能、给谁用？」是两个问题，拆开
4. **不用否定式** ——「你是不是不想要 X？」容易被答反，改成「X 要不要」
5. **同一维度不超过 2 轮** —— 第 3 轮还问不出来，换题型
6. **情绪高时先接住** —— 用户在抱怨时先共情一句，再问细节
7. **每轮给进度条** —— `确凿度 5/8 ▰▰▰▰▰▱▱▱`，让用户知道还要几轮
8. **用户说「你定」就定** —— 不要反复确认，直接定并记入决议日志，标「AI 代决」
